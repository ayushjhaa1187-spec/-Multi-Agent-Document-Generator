## 2024-05-23 - Dynamic Character Counter
**Learning:** Combining `aria-describedby` with a visual character counter improves form accessibility significantly without cluttering the UI. Users with screen readers can check the limit, while sighted users get immediate feedback.
**Action:** For all limited text inputs, implement a character counter and link it via `aria-describedby`.
## 2024-05-15 - Chat Input Auto-Resizing Textarea
**Learning:** When implementing auto-resizing textareas in Next.js React components (e.g., marked with 'use client'), use `useEffect` instead of `useLayoutEffect` to avoid SSR warnings. Avoid inline `ref` callbacks for DOM style mutations as they evaluate on every render, causing layout thrashing. To prevent scroll-jumping, store the textarea's current `scrollTop` and `window.scrollY` before resetting the height to 'auto', and restore them immediately after setting the new `scrollHeight`. Also, when placing an auto-resizing `<textarea>` inside a Tailwind `flex` row alongside other interactive elements (like a submit button), apply alignment classes such as `items-end` or `items-start` to the flex container to prevent sibling elements from unintentionally stretching vertically as the textarea expands. The chat input should handle `onKeyDown` to submit on Enter safely handling IME composition (`!e.nativeEvent.isComposing`), blocking submission if `!input.trim()` or `isLoading` is true, allowing Shift+Enter for newlines, and dynamically adjusting height based on `scrollHeight`.
**Action:** Always use `useEffect` and preserve scroll positions when making auto-resizing textareas, ensure flex containers use `items-end` or `items-start` to prevent sibling stretching, and properly handle form submission on Enter.
