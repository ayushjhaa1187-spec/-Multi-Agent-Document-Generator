## 2024-07-04 - Removed Redundant DB Health Check in Chat API
**Learning:** Found explicit database health checks (`await prisma.$queryRaw\`SELECT 1\``) inside the main Next.js API route (`/api/chat/route.ts`). In a Prisma application, Prisma automatically manages its connection pool. Manual explicit checks on every API route execution block the execution sequence and add unnecessary 10-50ms+ network latency per request. This is a common anti-pattern, especially in Serverless functions where connection management is sensitive to cold starts and pool limits.
**Action:** Removed the manual check, leaving standard query failures to handle unreachable database states. Next time working on Prisma-backed endpoints, ensure we do not explicitly write connection keepalives or health pings inline with business logic.
