## 2024-04-16 - Leaked Stack Traces via Public Analytics Endpoint
**Vulnerability:** The application was capturing `error.stack` inside `AnalyticsTracker.trackError()` which stores events in memory. These events were then exposed publicly without authentication via the `app/api/analytics/route.ts` endpoint (which returns `analyticsTracker.getEvents()`), potentially leaking sensitive internal implementation details, file paths, and environment context to anyone.
**Learning:** In applications where internal analytics or monitoring state is exposed (even partially) to clients without robust authentication, sensitive fields such as `stack` traces must be sanitized or omitted at the time of recording, not just filtered at the endpoint level, to prevent accidental leakage if other parts of the system interact with the same tracking utility.
**Prevention:** Always omit or sanitize stack traces and raw error objects from public-facing analytics or client telemetry systems. Retain full error objects and stack traces only in internal server-side logs (e.g., `console.error` in API routes) for observability. Ensure any publicly accessible endpoint strictly curates the data it returns.
