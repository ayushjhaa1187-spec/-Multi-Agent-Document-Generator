## 2025-04-14 - Information Leak via Unsanitized In-Memory Analytics
**Vulnerability:** Stack traces and internal server errors from `trackError` calls were being stored in an in-memory event array (`analyticsTracker.events`). This array was directly exposed without sanitization via the unauthenticated `GET /api/analytics` endpoint, leading to an information disclosure risk where external users could access internal error details.
**Learning:** In-memory caching/logging structures that are exposed directly to public endpoints (like metrics or analytics APIs) represent a unique information leakage vector in this Next.js application architecture. We must be extremely careful to sanitize the data at the source before pushing it to memory.
**Prevention:** Do not append sensitive fields (like `error.stack`) to objects destined for arrays/caches that power public API endpoints. Ensure analytics tracking utilities only record user-facing or sanitized error representations.
