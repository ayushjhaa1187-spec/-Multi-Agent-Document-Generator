## 2024-05-14 - Information Leakage via Public Analytics Endpoint
**Vulnerability:** The `trackError` method in `lib/analytics.ts` was including the error's stack trace in the tracked event properties. These events were then exposed publicly without authentication via the `app/api/analytics/route.ts` endpoint, leading to a critical information leakage vulnerability where internal application paths and execution flows were exposed to unauthenticated users.
**Learning:** Even internal tracking tools can become vectors for sensitive data exposure if their data is later exposed via public APIs (e.g., for dashboarding or health checks). Error stack traces should never be included in data that might cross trust boundaries or be exposed to unauthenticated clients.
**Prevention:** Sanitize error objects before tracking them. Only include generic error messages or error codes in tracking payloads, and explicitly omit stack traces or internal system details. Always assume tracking data might be exposed if it's accessible via an API.
