## 2026-04-26 - Fix Information Leakage via Public Analytics Endpoint
**Vulnerability:** The `AnalyticsTracker` was recording complete error objects, including stack traces, into its in-memory event array. These events were then publicly exposed without authentication via the `/api/analytics` endpoint. This could leak sensitive internal application paths and logic to an attacker.
**Learning:** In applications where analytical or debugging endpoints are intentionally or unintentionally made public, in-memory generic tracking arrays can become a vector for information leakage. The disconnect between where the data is stored (`lib/analytics.ts`) and where it is exposed (`app/api/analytics/route.ts`) masked the security risk.
**Prevention:** Always sanitize sensitive error data, especially stack traces, before adding them to generalized logging arrays or metrics stores that might be served via API endpoints. Implement strict boundaries between internal debugging logs and public-facing telemetry.
