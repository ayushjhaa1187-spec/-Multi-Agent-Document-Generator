## 2025-04-23 - Prevent Stack Trace Leakage in Public Analytics Endpoint
**Vulnerability:** The application's analytics tracker (`lib/analytics.ts`) captured raw `Error` stack traces and stored them in the `properties` of its internal `events` array. The `/api/analytics` endpoint publicly exposed these recent events via an unauthenticated GET request, leading to potential information leakage regarding internal application paths, logical flows, and underlying stack architecture.
**Learning:** Public or semi-public diagnostic endpoints should never serve unsanitized error objects directly from memory. In an architecture where memory events are directly serialized and exposed, the sanitization must occur at the tracking layer (before the data enters the tracked state) rather than solely relying on the API endpoint to filter the output.
**Prevention:** Always extract and log sensitive details (like stack traces) internally (e.g., using `console.error`) while sanitizing the payload before it enters the application's global or exposed state.
