## 2024-04-22 - Stack Trace Leakage via Public Analytics Endpoint
**Vulnerability:** The `AnalyticsTracker` utility in `lib/analytics.ts` included full error stack traces in tracked events, which were then exposed publicly via the unauthenticated `/api/analytics` GET endpoint. This led to unintentional information leakage of the server's internal state and code paths.
**Learning:** In-memory analytics arrays exposed via public API endpoints can easily become vectors for information leakage if sensitive data (like stack traces) is attached to generic event properties. The architectural pattern of dumping all recent events without a sanitization layer specifically before serialization creates a structural risk.
**Prevention:** Always maintain a strict sanitization layer between internal tracking mechanisms and publicly exposed data feeds. Keep sensitive diagnostic information (like stack traces) confined to internal server logs (e.g., `console.error`) and ensure only sanitized error messages are added to memory structures meant for potential API exposure.
