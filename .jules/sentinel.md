## 2025-02-18 - Prevented Stack Trace Leakage in Public Analytics Endpoint
**Vulnerability:** The `AnalyticsTracker.trackError()` method in `lib/analytics.ts` captured and included the full stack trace of errors inside the in-memory analytics event array. Because `app/api/analytics/route.ts` exposes these stored events via an unauthenticated, public GET request, it inadvertently leaked sensitive server-side stack trace information to any client accessing the analytics endpoint.
**Learning:** In-memory caching and logging structures intended for public metrics endpoints must be strictly sanitized. Even seemingly harmless utilities like `AnalyticsTracker` can create dangerous indirect pathways for information disclosure if they persist sensitive data that a separate, unauthenticated route subsequently exposes.
**Prevention:** Always filter out `stack` and other sensitive environment-specific error details from data structures that may be returned to the client. Keep full error logs (including stack traces) restricted to internal server-side logging mechanisms (e.g., `console.error`) to retain observability without jeopardizing security.
