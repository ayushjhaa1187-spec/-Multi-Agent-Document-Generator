## 2024-06-04 - Stop Error Leakage in Analytics Exports
**Vulnerability:** The analytics class `AnalyticsTracker` was directly returning all event properties when exporting events with `getEvents`. If an error occurred and the `trackError` method was called, the error's stack trace was added to the `properties` object. This meant that calling the `GET /api/analytics` endpoint could expose internal server structure and details via the unscrubbed stack trace.
**Learning:** Returning unscrubbed raw data collected internally can inadvertently expose sensitive application internals when exported. Data collected for diagnostics (like stack traces) shouldn't be directly accessible in exported formats without sanitization, particularly when the route (`/api/analytics`) allows retrieving these records.
**Prevention:** Ensure that export features strip sensitive fields (like stack traces, PII) before outputting the raw internal event data. Implement data sanitization at the export boundary (e.g. `getEvents` mapping logic) rather than restricting how diagnostic data is logged internally.
