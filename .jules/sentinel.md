## 2024-03-21 - [Prevent Stack Trace Leakage in Analytics APIs]
**Vulnerability:** Internal error stack traces generated on the backend (`lib/analytics.ts`) were saved into an in-memory event array and exposed publicly through the `GET /api/analytics` endpoint. Stack traces leak detailed file paths, package versions, and potentially sensitive codebase structures to an unauthenticated external attacker.
**Learning:** In-memory tracking and event arrays used for general metrics must not store sensitive diagnostics (e.g. `error.stack`). A public "analytics" endpoint can be a source of data leakage if internal diagnostic events are directly aggregated without sanitization. While stack traces are valuable in structured server logs (like CloudWatch), they must be completely excluded from metrics or events served back to clients.
**Prevention:** Always filter out `stack` traces and sensitive diagnostic details before pushing error events to data structures that may be exposed via metrics endpoints. Maintain distinct logging strategies: one (rich, detailed) for secure internal logs and one (sanitized) for application analytics.
