## 2024-05-17 - Prevent Stack Trace Leakage in Analytics Endpoint
**Vulnerability:** The `AnalyticsTracker` in `lib/analytics.ts` captured and stored full `error.stack` traces in memory. These events were then publicly exposed via an unauthenticated `GET /api/analytics` endpoint, leading to the potential leakage of sensitive internal server state and file paths.
**Learning:** Even internal utility functions like analytics trackers must sanitize their data if that data is eventually exposed to clients or public endpoints. While full stack traces are useful for internal logging (e.g., `console.error`), they should never be appended to payloads destined for public consumption.
**Prevention:** Explicitly separate internal logging from public-facing analytics. Sanitize or strip sensitive properties (like `stack`) from error objects before storing them in memory or sending them over network endpoints. Use `console.error` to retain the stack trace internally for server-side observability.
