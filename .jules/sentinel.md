## 2026-03-20 - Information Exposure in Unauthenticated Analytics Endpoint
**Vulnerability:** The analytics system stored full error stack traces (`Error.stack`) in its internal events array when tracking errors via `AnalyticsTracker.trackError`. These events were then publicly exposed via the unauthenticated `GET /api/analytics` endpoint, which returned `analyticsTracker.getEvents(20)`. This could leak sensitive internal system details like file paths and module versions.
**Learning:** In-memory caching and logging structures that are exposed to clients via metrics APIs must be strictly sanitized to remove sensitive information like stack traces before storage. The `GET /api/analytics` endpoint is public and cannot be assumed safe for raw debugging data.
**Prevention:** Do not persist full error objects or stack traces into data structures that might be exposed externally. Log full errors server-side (e.g., using `console.error`) for observability, but sanitize the object that is added to the event queue.
