## 2024-06-15 - Prevent Information Disclosure in Analytics Tracker
**Vulnerability:** The `AnalyticsTracker` stored error stack traces in internal events (`properties.stack`) which were subsequently exposed via `analyticsTracker.getEvents()`. In `app/api/analytics/route.ts`, these internal tracking objects were directly returned as JSON responses on the analytics API endpoint.
**Learning:** Stack traces can contain sensitive internal system paths and potentially code snippets. Even internal metrics tracking arrays shouldn't retain stack traces if they are exposed over an API endpoint, since returning tracking state un-scrubbed can unintentionally disclose sensitive backend execution details.
**Prevention:** Destructure and scrub sensitive error properties (like `stack`) when serializing analytical events for API responses, while still maintaining the stack trace internally if strictly necessary, or simply scrub them during retrieval using the spread operator (`const { stack, ...safe } = properties;`).
