## 2024-05-20 - Information Leakage in Public Analytics API
**Vulnerability:** The `AnalyticsTracker` class in `lib/analytics.ts` captured and stored full error stack traces in its in-memory events array when `trackError` was called. These events were then exposed publicly via the unauthenticated `GET /api/analytics` endpoint, leading to the leakage of internal server details and code paths.
**Learning:** In-memory caching and logging structures that are exposed to clients or public APIs must be strictly sanitized. Even if a utility is designed for generic "tracking," the context of where that tracked data ends up (e.g., a public metrics endpoint) dictates its security requirements.
**Prevention:** Always sanitize sensitive information (like stack traces, user PII, or internal IDs) before adding them to publicly accessible state or in-memory arrays. Maintain a clear separation between internal server-side logging (which should retain full context for debugging) and client-facing metrics or analytics.
