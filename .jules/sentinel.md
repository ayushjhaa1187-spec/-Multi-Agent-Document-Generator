## 2024-05-18 - Prevent Sensitive Error Information Exposure in Analytics Tracking and API Logs
**Vulnerability:** The `AnalyticsTracker` in `lib/analytics.ts` was storing full error stack traces in its in-memory events array when `trackError` was called. Similarly, API error handlers in `app/api/chat/route.ts` were logging the full error object using `console.error`. Both of these practices could inadvertently expose sensitive application internals (like file paths, database queries, and code structure) to external entities if logs are forwarded or if the analytics events are exposed via metrics APIs.
**Learning:** The project relies heavily on an in-memory `AnalyticsTracker` singleton for monitoring, making it uniquely susceptible to metrics endpoint exposure if stack traces aren't sanitized before being added to the event array.
**Prevention:** Sanitization of `console.error` and telemetry storage must be explicitly handled in this codebase due to the nature of the application's in-memory telemetry gathering.
